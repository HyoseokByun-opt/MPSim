부록 C. 출력 파일

해석을 하나 실행할 때마다 작업 폴더 → 케이스 폴더 안에 폴더가 하나씩 생깁니다(3장 8절). 폴더 이름은 실행한 해석의 이름입니다 — 예: thermal+dielectric, 같은 해석을 또 돌리면 thermal+dielectric-02. 실행 시각과 고유 번호(예: 20260929-102025-87fa81)는 폴더 안 job.json에 기록됩니다.

이 안에 결과가 모두 들어 있습니다. 프로그램을 통하지 않고 직접 열어 다른 도구로 분석할 수도 있습니다.

C.1 폴더 구성

파일내용
result.json 가장 중요한 파일입니다. 화면과 보고서에 나오는 모든 수치의 원본이 들어 있습니다. 물성 텐서, 파생 수치, 분포, 검증 항목 전체가 여기 있습니다. 다른 도구로 후처리하려면 이 파일을 읽으십시오.
report.html 자동 생성된 보고서(27장). 브라우저로 바로 열립니다.
spec.json 사용자가 입력한 설정 그대로.
spec.normalized.json 프로그램이 기본값을 채우고 단위를 정리한 실제로 계산에 쓰인 설정입니다. 결과를 재현하려면 이 파일을 쓰십시오.
job.json 실행 상태와 이력(시작·종료 시각, 단계별 진행).
layer_card.json 이 재료의 물성을 한 층(layer)의 요약 카드로 정리한 것. 상위 해석에 물성으로 넘길 때 쓰는 형식입니다.
structure.tif 생성된 3차원 구조(8-bit ImageJ stack, voxel 크기 포함). 재료(region)마다 다른 grey value를 0~255 사이에 고르게 줍니다 — matrix 0, 마지막 region 255. 어느 viewer에서 열어도 재료가 구분되고, 다른 프로그램에서 threshold로 나눌 수 있습니다.
structure_labels.tif 같은 구조의 material ID map(0, 1, 2, …). 값을 그대로 재료 번호로 쓰는 프로그램에 넣습니다.
structure_legend.csv ID ↔ grey value ↔ 재료 이름·종류(matrix/core/shell)·부피분율·void 여부·해석에 쓴 물성(k, σ, εr, tanδ, μr, E, ν, α, ρ, cp)과 voxel 크기·격자 크기. 다른 해석 소프트웨어로 같은 해석을 재현할 때 이 표대로 재료를 지정합니다.
run.log 실행 기록. 문제가 생겼을 때 가장 먼저 볼 파일입니다(부록 D).
figures/ 서버에서 렌더링한 PNG 그림들 — 구조 3D·단면, 각 필드의 3D·단면, 경로 그림.
view/ 화면 표시용 데이터. 아래 참조.
structure/ 생성한 구조의 원본 — 복셀 지도(.npz, 압축)와 입자 목록(.pkl). 파일 이름은 구조를 정하는 입력(형상·크기·함량·격자·접촉 처리·seed)의 지문입니다. 같은 구조로 해석을 추가하거나 재료만 바꿔 다시 돌릴 때 구조를 다시 만들지 않고 여기서 읽습니다(2.4절). 지워도 결과에는 영향이 없고, 다음 해석에서 구조를 새로 만들 뿐입니다.

C.2 view 폴더 — 필드 데이터

3D 화면에 그려지는 값들이 가공되지 않은 이진 형식으로 들어 있습니다. 직접 읽어 자체 후처리를 할 수 있습니다.

파일내용
meta.json 먼저 읽어야 할 파일입니다. 격자 크기(nx, ny, nz), 복셀 크기, 어떤 필드가 있는지, 각 필드의 이름·단위·범위가 들어 있습니다.
labels.u8 각 복셀의 상 번호. unsigned 8-bit, 배열 크기는 nx·ny·nz.
field_<해석>_<방향>_<양>.f32 스칼라 필드. 32-bit float, little-endian. 예: field_thermal_x_T.f32는 x방향 가압 시의 온도장, field_thermal_x_q.f32는 열유속 크기.
vec_<…>.f32 벡터 필드. 복셀당 3개의 float(x, y, z 성분)가 이어집니다.
paths_<…>.json 유선·역선·입자 경로의 좌표열. 각 선마다 점의 목록과 관통 여부가 들어 있습니다.
surf_1.bin 입자·기공 표면의 삼각형 메시(Smooth 표시). 입자마다 따로 만든 표면이 상(phase)별로 한 파일에 모여 있습니다.
vox_1.bin 같은 상의 복셀 면(Voxels 표시): 공유 꼭짓점(uint16 격자 좌표), 사각형, 그리고 사각형마다 그 뒤 복셀의 view 격자 번호 — 이 번호로 필드 값을 찾아 면을 칠합니다.
surf_1_<…>.f32 그 표면의 각 꼭짓점에 대응하는 필드 값(표면을 값으로 칠할 때 씁니다).
파이썬으로 필드를 읽는 예 — meta.json에서 격자 크기를 읽고 그대로 reshape하면 됩니다.
import json, numpy as np
m = json.load(open("view/meta.json"))
nx, ny, nz = m["nx"], m["ny"], m["nz"]
T = np.fromfile("view/field_thermal_x_T.f32", dtype="<f4").reshape(nz, ny, nx)
축 순서는 meta.json에 함께 기록되어 있으므로 그 표기를 따르십시오.

C.3 구조를 다른 해석 프로그램으로 — 비교 계산

Results 탭의 Structure TIFF set은 structure.tif, structure_labels.tif, structure_legend.csv 세 파일을 한 ZIP으로 내려받습니다. 같은 RVE를 다른 voxel 해석 프로그램에서 풀어 결과를 비교하는 절차는 다음과 같습니다.

  1. 구조 가져오기 — structure.tif(grey 단계)를 image stack으로 읽고, legend의 grey value마다 material ID를 지정합니다. 값을 곧바로 재료 번호로 쓰는 import라면 structure_labels.tif를 읽습니다.
  2. voxel 크기 — legend의 voxel_size_um을 넣습니다(TIFF의 ImageJ 해상도에도 들어 있습니다).
  3. 재료 물성 — legend의 k, εr, E, ν, α 등을 그대로 지정합니다. void = 1인 region은 pore(기체)입니다.
  4. 경계 조건 — 이 프로그램은 모든 방향 periodic으로 풉니다. 비교할 때도 periodic 조건을 쓰십시오. interfacial resistance(Rint, Rc)를 넣었다면 상대 프로그램에도 같은 계면 조건을 줘야 합니다.
축 순서는 ImageJ 관례대로 파일 안에서 (z, y, x)입니다 — 첫 번째 image가 z = 0 단면입니다. 격자와 voxel 크기가 같으면 두 프로그램의 구조는 voxel 하나까지 같습니다. v3의 structure.tif는 region 번호(0, 1, 2 …)만 담아 viewer에서 검게 보였고, v4부터 grey 단계와 label map을 나누어 냅니다.

C.4 DOE 연구의 출력

DOE는 케이스마다 위와 같은 폴더를 하나씩 만들고, 이름에 그 케이스가 바꾼 인자의 값을 씁니다 — 예: doe-HGM-t-0.526817-vf-29.1782(두께 0.53 µm, 함량 29.2 vol%). DOE 케이스들은 연구를 만들 때 열려 있던 케이스 폴더 아래에 모입니다. 연구 전체의 요약은 DOE 탭의 CSV로 내려받는 것이 가장 편합니다 — 인자와 응답이 한 줄에 정리된 표입니다.

C.5 폴더를 옮기거나 지울 때

상황주의
결과를 보관하고 싶다 폴더째 복사하면 됩니다. 다른 PC의 작업 폴더에 넣으면 목록에 나타납니다.
용량을 줄이고 싶다 view/ 폴더가 가장 큽니다. 지우면 3D 화면은 볼 수 없지만 수치와 보고서는 그대로 남습니다.
다른 사람에게 보낸다 Report 탭의 Complete ZIP을 쓰는 편이 안전합니다. 필요한 것이 빠짐없이 들어갑니다.
