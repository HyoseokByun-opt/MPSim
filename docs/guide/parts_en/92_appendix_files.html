Appendix C. Output files

Every analysis run creates one folder inside work folder → case folder (section 3.8). The folder is named after the analyses run — e.g. thermal+dielectric, and thermal+dielectric-02 when the same analyses run again. The run time and a unique number (e.g. 20260929-102025-87fa81) are recorded in job.json inside the folder.

Everything about the result is in there. The files can be opened directly and analysed with other tools, without the program.

C.1 Folder contents

FileContent
result.json The most important file. It holds the source of every number on screen and in the report: property tensors, derived numbers, distributions and all verification items. Read this file for post-processing in other tools.
report.html The automatically generated report (chapter 27); opens directly in a browser.
spec.json The settings exactly as the user entered them.
spec.normalized.json The settings actually used, with defaults filled in and units normalised by the program. Use this file to reproduce a result.
job.json Run status and history (start and end times, progress per stage).
layer_card.json The properties of this material as a summary card for one layer — the format for handing properties to a higher-level analysis.
structure.tif The generated 3D structure (8-bit ImageJ stack with the voxel size). Each material (region) gets its own grey value, spread evenly over 0–255 — matrix 0, last region 255 — so materials are distinguishable in any viewer and separable by thresholds in other programs.
structure_labels.tif The material ID map (0, 1, 2, …) of the same structure, for programs that use the values directly as material numbers.
structure_legend.csv ID ↔ grey value ↔ material name, kind (matrix/core/shell), volume fraction, void flag, the properties used (k, σ, εr, tanδ, μr, E, ν, α, ρ, cp), voxel size and grid size. Assign materials by this table to reproduce the same analysis in other software.
run.log The run log — the first file to look at when something goes wrong (Appendix D).
figures/ PNG figures rendered on the server — structure 3D and sections, 3D and sections of each field, path figures.
view/ Data for the on-screen view; see below.
structure/ The original of the generated structure — voxel map (.npz, compressed) and particle list (.pkl). The file name is a fingerprint of the inputs that define the structure (shapes, sizes, contents, grid, contact handling, seed). Adding analyses to the same structure, or rerunning with other materials only, reads it from here instead of generating it again (section 2.4). Deleting it does not affect results; the next analysis simply generates the structure anew.

C.2 The view folder — field data

The values drawn in the 3D view, in raw binary form. They can be read directly for custom post-processing.

FileContent
meta.json The file to read first. Grid size (nx, ny, nz), voxel size, which fields exist, and the name, unit and range of each.
labels.u8 Phase number of each voxel, unsigned 8-bit, nx·ny·nz values.
field_<analysis>_<direction>_<quantity>.f32 Scalar fields, 32-bit float, little-endian. E.g. field_thermal_x_T.f32 is the temperature under an x gradient, field_thermal_x_q.f32 the heat-flux magnitude.
vec_<…>.f32 Vector fields: three floats (x, y, z components) per voxel in sequence.
paths_<…>.json Coordinates of streamlines, field lines and particle paths: a list of points per line and whether it crossed the RVE.
surf_1.bin Triangle mesh of particle and pore surfaces (Smooth display): the surfaces built per particle, gathered per phase in one file.
vox_1.bin Voxel faces of the same phase (Voxels display): shared vertices (uint16 grid coordinates), quads, and for each quad the view-grid index of the voxel behind it — used to look up the field value that colours the face.
surf_1_<…>.f32 Field values at each vertex of that surface (for colouring surfaces by value).
Reading a field in Python — read the grid size from meta.json and reshape.
import json, numpy as np
m = json.load(open("view/meta.json"))
nx, ny, nz = m["nx"], m["ny"], m["nz"]
T = np.fromfile("view/field_thermal_x_T.f32", dtype="<f4").reshape(nz, ny, nx)
The axis order is recorded in meta.json; follow that notation.

C.3 Taking the structure to another solver — comparison calculations

Structure TIFF set in the Results tab downloads structure.tif, structure_labels.tif and structure_legend.csv in one ZIP. To solve the same RVE in another voxel-based program and compare results:

  1. Import the structure — read structure.tif (grey levels) as an image stack and assign a material ID to each grey value of the legend. An import that takes values directly as material numbers reads structure_labels.tif.
  2. Voxel size — enter voxel_size_um from the legend (it is also in the ImageJ resolution of the TIFF).
  3. Material properties — assign k, εr, E, ν, α and so on from the legend as they are. Regions with void = 1 are pores (gas).
  4. Boundary conditions — this program solves with periodic conditions in every direction; use periodic conditions in the comparison too. If interface resistances (Rint, Rc) were used, give the other program the same interface conditions.
Following the ImageJ convention, the axis order inside the file is (z, y, x) — the first image is the z = 0 section. With the same grid and voxel size, the structures in both programs match voxel for voxel. In v3, structure.tif held only region numbers (0, 1, 2 …) and looked black in viewers; since v4 grey levels and the label map are written separately.

C.4 Output of a DOE study

A DOE creates one such folder per case, named with the factor values that case changed — e.g. doe-HGM-t-0.526817-vf-29.1782 (thickness 0.53 µm, content 29.2 vol%). The DOE cases gather under the case folder that was open when the study was created. For a summary of the whole study, the CSV download of the DOE tab is most convenient — a table with factors and responses on one row.

C.5 Moving or deleting folders

SituationNote
Archiving results Copy the whole folder. Placed in a work folder on another PC, it appears in the list.
Saving space The view/ folder is the largest. Deleting it disables the 3D view but keeps the numbers and the report.
Sending to someone Complete ZIP in the Report tab is safer: everything needed goes in.
