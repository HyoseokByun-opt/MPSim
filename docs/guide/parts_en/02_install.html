2. Installation and a first analysis

2.1 Installation

There are two ways to install. On a PC without internet access, such as one on a secured network, the whole package is copied and installed — conda (Miniconda/Anaconda) is not needed. On a PC with internet access the environment can also be created with conda.

SituationFile to runWhat it needs
PC without internet (recommended)1_INSTALL_OFFLINE.bat Nothing. Python and every package, NASA PuMA included, are in the package.
PC with internet1_INSTALL.bat conda. It creates an environment in env\ from conda-forge (about 2–3 GB).

Offline installation (no conda)

  1. Copy the whole folder to the PC, on a short path (for example C:\MPSim\). Some packages create deep folders; on a long path the installation stops at the 260-character path limit of Windows with "file name too long" (WinError 206). The installer warns beforehand when the path is long.
  2. 1_INSTALL_OFFLINE.bat — uses no internet at all. It does three things:
    • unpacks the official Python 3.11 runtime of runtime\ (the embeddable distribution from python.org) into a python\ folder, registering nothing in Windows;
    • installs the 76 packages of wheels\ (NASA PuMA included) into it;
    • checks that every component imports and runs the short self-test (38 checks).
  3. 2_RUN_LOCAL.bat — starts the program; the browser opens by itself.
Installing means creating one python\ folder beside the program (about 1.6 GB), nothing more. Deleting that folder undoes it completely. The launchers use python\ when it exists and look for a conda environment only when it does not.

Contents of the offline package

ItemContent
runtime\python-3.11.9-embed-amd64.zipOfficial Python 3.11 runtime (11 MB)
wheels\Every package needed (76 wheels, about 235 MB).
requirements-offline.txtThe packages and versions to install — the versions that passed the self-test.
constraints-offline.txtVersions that must not be exceeded (numpy < 2, scipy 1.11, vtk 9.5.2) — PuMA is built against them.
tools\build_offline.pyThe script that builds the package (run once on a PC with internet).
tools\check_imports.pyReports what imports and what is missing.

Why NASA PuMA works without conda

PuMA is distributed only on conda-forge, but what the conda package actually installs is an ordinary Python package (pumapy). Its four compiled modules need only python311.dll, VCRUNTIME140.dll (part of every python.org Python) and the Windows C runtime; they rely on no other library of the conda environment. tools\build_offline.py therefore packs the installed PuMA into a standard wheel (pumapy-3.2.2-cp311-cp311-win_amd64.whl), which the offline PC installs like any other package. PuMA is distributed under the NASA Open Source Agreement 1.3, and its licence file travels inside the wheel.

Verification — the package was installed with conda removed from the PATH (only the Windows folders left). The short self-test (38 checks) and three complete pipelines (filled composite, thin film, porous body) all passed, with the same numbers as in the conda environment (for example k = 0.4015 W/m·K).

Building the package again (PC with internet)

conda run -p .\env python tools\build_offline.py

It downloads the Python runtime, builds the wheel from the PuMA in that PC's conda environment and downloads every other package as a wheel for Windows and Python 3.11. Then the whole folder is moved to the offline PC.

Serving other PCs

Started with 3_RUN_SERVER.bat, the program can be opened in a browser from other PCs on the same network. The server PC does the solving, so one powerful PC serving several users is the efficient arrangement. If other PCs cannot connect, 4_NETWORK_CHECK.bat tells whether a firewall or wireless isolation is the cause.

Always start the program with the .bat files

The numbered .bat files decide, through _common.bat, which Python to use (python\ → env\ → a conda environment) and set the console encoding to UTF-8. Always start the program with them.

2.2 A first analysis, step by step

The quickest start is a preset. Following the steps below gives a first result within five minutes.

① Choose a preset

The left panel of the Home tab holds typical problems. Clicking, for example, EMC · epoxy + fused silica 50 vol% fills in the materials, the structure and the analyses at once. Under each preset the analyses it switches on are listed.

② Build the structure

In the Structure tab, click Generate structure. Nothing is solved: only the structure is built and shown in 3D, so that the filler content and the sizes can be checked by eye first. The structure is kept in that run, and when the analyses are run in step ⑤ it is used as it is instead of being generated again (section 2.4).

③ Set the resolution

The Domain tab shows the voxel size and the RVE size. The automatic setting is fine to begin with. When a value is changed, the expected grid appears at once below, with a warning if a criterion is not met (chapter 6).

④ Choose the analyses

Switch on what is needed in the Simulation and Structure Analysis tabs. Several can be on at once. The ribbon icons and the switches on the cards in the left panel both toggle them.

⑤ Run

Click Run at the top right. The progress scrolls in the Console below, and intermediate results appear as they come. When the run finishes, the Result Viewer opens by itself.

2.3 Recommended settings for a first run

SettingRecommendedWhy
Accuracy levelStart with Fast Enough to see trends, and much faster. Run again at Standard or above when numbers for a report are needed.
Load directionsz, x and y Shows whether there is anisotropy. When time is short, z (through the thickness) alone will do — fields and arrows are stored for the first direction, z.
AnalysesOnly what is needed Elasticity and CTE solves seven load cases and takes longest. Analyses added later do not rebuild the structure (section 2.4).
Realisations1 Two or more give the scatter, with a 95 % confidence interval.
The solving time grows with the cube of the grid. Halving the voxel size makes the grid eight times larger, and the time grows by more than that. Start coarse and refine only as far as needed.

2.4 Continuing with the same structure

A run keeps the structure it built in its structure\ folder (the voxel map and the particle list). When a new analysis starts, the program looks among the runs of the same work folder and case for the same structure (same shapes, sizes, contents, grid, contact handling and seed) and, if there is one, proceeds as follows.

SituationWhat happens
Run after Generate structure The structure-only run continues as an analysis run. The structure is not generated again, and no extra run is created.
Analyses added to a finished run (e.g. thermal → thermal + dielectric) That run continues. The analyses already there are kept and only the new ones are solved, merged into the results, the report and the 3D fields. The folder name follows the analyses it holds (thermal → dielectric+thermal).
Nothing newThe program says that everything is already there and solves nothing.
Material properties or analysis options changed The results would differ, so a new run is created — but it takes over the structure of the earlier run. The earlier results are kept.
Shapes, contents, grid or seed changedA different structure, generated anew.

A run open on screen that matches takes precedence. To turn this behaviour off, clear Reuse the structure of a matching run in the Simulation tab.
