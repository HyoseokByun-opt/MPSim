29. Optimization — surrogate models and optimisation

Open-source codes: scikit-learn Gaussian processes, SciPy global optimisation. Sobol indices and NSGA-II are own implementations

The results gathered by a DOE are not left as they are: a predictive model is built and used to find the optimum. This tab separates the two into distinct stages.

29.1 Why two stages

A stage switch sits at the top of the screen.

StageWhat it doesThe question it answers
1 · Surrogate model Trains a model on the finished runs and scores it by cross-validation. Can this model be trusted?
2 · Optimisation Searches the model — an optimum for one response, a trade-off front for several. So what should be made?
Doing both with one button would mean accepting an optimum without checking that the model is any good. The optimum is the model's product; a poor model gives a poor optimum. Hence the enforced order.

A DOE study is needed first (chapter 28). Choose the study, the response and the goal (Maximise / Minimise / Reach a target) and press Run optimisation.

How the accuracy is scored

As the screen explains, each point is predicted by a model trained without it (leave-one-out cross-validation). It measures not how well the model memorised its own data but how wrong it will be under conditions it has not seen.

Choosing the model — Surrogate tuning in the left panel

Which model fits well is a property of the response, not a setting fixed once, so it is left open to change.

SettingWhen to change it
Model Matérn 5/2 (default, smooth) · 3/2 · 1/2 (rough responses) · RBF (very smooth) · quadratic surface (few points). Retrain after changing and compare R².
Noise Left empty, it is estimated automatically. Given a value, the model does not force itself through the scatter — particularly important here, where every case generates its structure from new random numbers.
Restarts How many times the likelihood optimisation restarts. Raise it when results are unstable.
Changing the settings does not retrain automatically. Seeing how R² changes should be a deliberate action, so press Run optimisation again.

Total indices summing to more than 100 % is normal: the interaction share is counted on both sides. In the example the content dominates and the size is secondary, which makes clear where to spend the design effort.

The optimum (50, 3) sits at a corner of the search range. That almost always means "the true optimum lies outside the range". Density naturally rises with AlN; the thing to do is widen the content range and run the DOE again. Only an optimum inside the range carries meaning.

The Suggested next run is the point of largest expected improvement, weighing places predicted good against places still unknown. The example's diameter 2.673 lies in a stretch never checked, since the DOE ran only 1 and 3. Two buttons put that condition straight into the queue to check the prediction by computation.

29.5 Stage 2 — several objectives at once (NSGA-II)

In real design one usually wants more than one thing, and the wishes conflict. More filler raises the thermal conductivity but adds weight. Then no single best design exists; what remains is the set of designs in which nothing can be improved without giving something else up — the Pareto front, which NSGA-II finds.

Choose two or more responses, set max/min for each, and press Find the trade-off front.

By example — a light material that conducts well

Minimising density while maximising thermal conductivity makes the two collide head-on. The front from the study of example A:

EndDensityThermal conductivity
Lightest1.590 g/cm³0.429 W/m·K
Best conducting2.207 g/cm³1.131 W/m·K

Everything in between is a possible design. All this table says is that raising the conductivity 2.6 times costs 39 % more density; choosing by that exchange rate is the design decision. The screen also marks the best-balanced point (the knee).

Without a conflict the front is a single point. Setting density and conductivity both to maximise, more AlN improves both, nothing conflicts, and the screen shows "Trade-off points 1". Not an error but the answer "there is nothing to weigh".
A front is only as trustworthy as the models beneath it. The screen shows R² per response. In the example above density has R² 0.694 but thermal conductivity 0.044 — practically no predictive power. The vertical axis of this front cannot be trusted, and no conclusion should be drawn before more points are gathered. In such a case "the model is not good enough yet" is a more important result than the shape of the front.

29.6 Recommended order

  1. Sweep widely with a DOE (chapter 28).
  2. In stage 1 see which factors matter; if R² is low, try another model.
  3. If the optimum sits at a corner of the range, widen the range and rerun.
  4. Add a few points with Queue the suggested run and retrain.
  5. Once R² is high enough, go to stage 2 and read the optimum or the trade-off front.
  6. Run one more real analysis at the chosen condition to confirm the prediction.

29.7 Limits

ItemDescription
No predictions outside the range Valid only within the range swept by the DOE; no extrapolation.
Few points, weak model Five to ten points per factor are needed. Until then the Sobol indices and regression coefficients are more reliable.
Computational uncertainty is unknown Each run's value is trained as exact. For responses that scatter with the seed, the scatter enters the model error — the Noise setting mitigates it.
Manufacturability is not judged Whether the optimum can actually be made is unknown; geometrically impossible regions may exist, like the failed case of chapter 28.
